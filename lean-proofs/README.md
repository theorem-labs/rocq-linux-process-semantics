# `lean-proofs/`: released OSS Verify statements, in Lean, over the twin

`lean/` of this repository is the Lean twin of the Rocq model beside it. This
directory holds Lean proofs of theorem-labs/oss-verify-proofs-internal's
RELEASED statements, stated over that twin — not over SailProc, which is what
the Lean proofs in oss-verify-proofs-internal use.

One directory per harness: `lean-proofs/<project>/<harness>/`, a Lake package
of its own that `require`s the twin at `../../../lean`.

Today there is one, `libreac/fuzz_knock`, built by OSSV-265 slice K1.

## Building one

The package takes the twin from `../../../lean`, which is this repository's own
`lean/`, so a checkout needs no setting:

```sh
cd lean-proofs/libreac/fuzz_knock
lake build                      # the library
lake build OssFuzzTheorems.Axioms   # and print the axiom walk
```

A cold build is about 10 minutes, almost all of it the two image modules; an
incremental one is seconds. Build it on a VM, not on a shared box: the image
modules hold about 2.2 GB each while they compile.

Where the twin is elsewhere — a checkout of theorem-labs/linux-process-semantics
at `ff0313ba4f`, whose `lean/` is the same content — make `<repo>/lean` a
symbolic link to it.

## The three rules a harness directory follows

1. **The Rocq definition is the source.** Every file's first line names the
   file it ports and the commit:
   `-- Ports oss-verify-proofs-internal ossv/recipes 9b0ac6f0e6:<path>` for a
   statement or a proof, `-- Ports rocq-linux-process-semantics f1006fe8:<path>`
   for a file that ports the model. Every declaration cites the Rocq
   declaration it comes from, by file and line span.
   `python3 tools/rocqspan.py check <files>` checks each of those citations
   against the Rocq declaration of the same name at the pinned commit, and
   refuses a citation it cannot attach until an `EXPECT` entry says what it
   names. Run it before you push: slice K1 opened with 27 wrong citations, two
   of them naming the wrong file.
2. **The image is the trusted part, so something must check it.**
   `Image/<Build>.lean` is generated by `tools/gen_image.py` from the ELF that
   the harness's `harness.yaml` pins by SHA-256. Its records ARE the program
   the statement is about and no Lean proof checks them against the ELF;
   `tools/check-images.sh` does, and it must pass whenever an image module
   changes. The code module beside it is NOT trusted: every `F_<pc>` fetch and
   `D_<pc>` decode is closed by `decide +kernel` against the twin's own
   decoder and the image's own bytes, so a wrong proposal fails to compile.
3. **`#print axioms` is the gate, not a search for `sorry`.** In Lean `stop` is
   `repeat sorry`. Each package carries an `Axioms.lean` that prints every
   theorem a reader should care about; each must list `propext`,
   `Classical.choice` and `Quot.sound` and nothing else.

## What a harness directory holds

| path | what |
| --- | --- |
| `OssFuzzTheorems/Core/Shapes.lean` | the twin of `theories/Shapes.v`: what every released statement says |
| `OssFuzzTheorems/Core/Images.lean` | the twin of `theories/Images.v`: when an image is well formed |
| `OssFuzzTheorems/<project>/<harness>/Statements.lean` | the released statements, word for word |
| `…/Images.lean`, `…/Image/*.lean` | the images, generated, with their byte certificates |
| `…/proofs/lib/` | the twin of the harness's Rocq proof library |
| `OssFuzzTheorems/Axioms.lean` | the axiom walk |
| `tools/` | `gen_image.py`, `check-images.sh`, `rocqspan.py` |

## Generating an image

```sh
python3 tools/gen_image.py <elf> --out-dir OssFuzzTheorems/<p>/<h>/Image \
  --module OssFuzzTheorems.<p>.<h>.Image --name Plain --sha256 <the harness.yaml pin> \
  --code 0x12adc:628 --code 0x12d50:76          # one range per function a proof walks
bash tools/check-images.sh <dir holding the ELFs>
```

A run of one repeated byte becomes a single chunk, because
`List.all_replicate` decides it in one step however long it is, and a chunk's
`String` is DEFINED as `String.ofList` of its character list so that
`_chars_eq` has nothing to compute. Both matter: with a chunk per 256 bytes
throughout, the image of a 43 KB binary did not compile in 44 minutes, and the
per-segment lemmas are what make it quadratic in the chunk count. See
`gen_image.py`'s docstring.
